# Tandem UI design: console direction

**Status:** the owner reviewed and approved the mockups on 2026-11-20.

**Inputs:**
- Product brief: [PRODUCT.md](../../../PRODUCT.md).
- Product spec: [2026-11-19-emulator-save-config-sync-design.md](2026-11-19-emulator-save-config-sync-design.md), §8 for the web UI and §9 for the Android app.
- Mockups: [design/mockups/](../../../design/mockups/). They are the visual reference. Where this text and a mockup disagree, this text wins.

## 1. Intent

**Who uses it, and how:**
- People who play emulated games on several handhelds and run their own server.
- They open the **web UI** for four reasons:
  - a notification told them something went wrong;
  - to check in on "where's my newest save?";
  - to set things up and tinker with configs;
  - rarely otherwise.
- They open the **app** briefly between play sessions, with a gamepad in hand.

**Feel:** like a game console's own system menus.
- Calm, quick to scan, and driven by a cursor.
- Quiet when everything is fine.
- Unmistakable when something needs them.

**Decisions the owner made in the Q&A:**

| Question | Decision |
|---|---|
| Theme | Light and dark, both designed with equal care. The theme follows the system and can be overridden in Settings. |
| Taste | Industrial hardware and console system UI. Direction B ("Console") was chosen, then refined to remove AI tells. |
| Game art | Small marks only: the system name as text. No box art. |
| Density | Dense, scannable lists. |
| App look | **The same look as the web UI**, not stock Material 3. The app is still built natively in Compose. |

## 2. What we refuse (the AI tells)

These are banned unless this document names an exception:
- Purple or indigo accents; gradients; glow; glass or blur.
- Cards inside cards. Lists sit directly on the page, divided only by hairlines.
- An accent bar on the left edge of an active item, a callout or a card.
- Icons inside coloured or rounded squares; emoji; Unicode symbols standing in for icons. Icons are drawn as SVG with one stroke weight.
- Number tiles (KPI boxes); progress rings; decorative sparklines.
- Status pills on every row; a coloured dot beside every name; "In sync" badges. When nothing is wrong, nothing is labelled.
- Small uppercase labels above headings. Column headers in tables are the only uppercase text.
- Explanatory subtitles under every heading. A subtitle appears only when it states a fact the reader needs.
- A blue-tinted near-black background. The dark theme is neutral.
- The same large radius on everything. The only radius is 3 px, used on the focused row and on buttons.
- Separate alert banners for a game's problem. The game's own row carries it, in red, pinned to the top.

## 3. Tokens

The names describe what each colour means, not how it looks. Every colour in the build maps to one of these.

| Token | Dark | Light | Meaning |
|---|---|---|---|
| `--bg` | `#121212` | `#EDEDEA` | the page; the only background |
| `--ink` | `#F2F2F0` | `#141414` | primary text |
| `--ink2` | `#A3A3A0` | `#55554F` | secondary text, values |
| `--ink3` | `#7E7E7B` | `#6B6B66` | metadata, column headers, disabled |
| `--rule` | `rgba(255,255,255,.07)` | `rgba(0,0,0,.09)` | row hairlines |
| `--rule2` | `rgba(255,255,255,.14)` | `rgba(0,0,0,.18)` | column dividers, button and input outlines |
| `--focus-bg` / `--focus-ink` | `--ink` / `--bg` | `--ink` / `--bg` | the cursor: an inverted row |
| `--wait` | `#F0A030` | `#9A5C00` | waiting for an emulator to close; a device is busy |
| `--fault` | `#FF6B55` | `#C23824` | needs you: a conflict, Shizuku off, a failed sync |
| `--glyph` | `#2A2A2A` | `#D6D6D1` | face-button discs in hints |
| `--diff-add` / ink | `rgba(110,170,255,.10)` / `#8EC0FF` | `rgba(0,103,214,.08)` / `#0057B8` | added lines in diffs |
| `--diff-del` / ink | `rgba(240,160,48,.10)` / `#F0B060` | `rgba(184,110,0,.10)` / `#8C5200` | removed lines in diffs |

Rules for colour:
- Status colour appears only on the words that carry the meaning, never as fills or backgrounds.
- The one exception is the diff view, where the line tints are what the data means.
- Diffs use blue and amber, not green and red, so colour-blind readers can tell them apart.
- Each status is also stated in words ("waiting", "two saves"), so colour is never the only signal.
- The ink3, wait, fault and light diff-del-ink values were raised from the first draft because they measured below 4.5:1 (3.66, 3.58, 3.40, 4.35 and 4.18); `web/test/tokens.test.ts` enforces the rule.
- All text meets WCAG AA (4.5:1) on `--bg` and on `--focus-bg`. On the cursor row, secondary text is `--focus-ink` mixed 62% toward `--focus-bg`.

## 5. Layout and density

- **Grid:** a 4 px base.
- **Web page padding:** 40 px at the sides.
- **Bars:** the top bar is 72 px and the hint bar is 56 px.
- **App** (832×468 dp landscape, the real size of the Thor's and the Odin 3's screens; the mockups were drawn at 960×540): side padding is 28 dp, the top bar 52 dp, the hint bar 44 dp. The app runs immersive: the status and navigation bars are hidden (a swipe shows them for a moment).
- **Row height:** 46 px for web lists, 44 px for detail lists, 40 dp in the app. Rows are dense on purpose.
- **Rows:** a row is a CSS grid with fixed columns. The game name truncates with an ellipsis and never wraps.
- **Two panes:** a list on the left and the detail of the focused item on the right, split by one `--rule2` vertical line. Used on the Game page, Configs, Setup, and the app's main and Conflicts screens.
- **Narrow web widths:** the panes stack, the top tabs scroll sideways, and tables scroll inside their own area. Phone width is supported but not designed for.

## 6. Components

**Top bar**
- On the left, the wordmark: the product name as plain text in Barlow Semi Condensed 700. No logo yet, since the product name is still undecided.
- Next, the page tabs flanked by **bumper hints** (`L1` and `R1`). The active tab is `--ink`, the others `--ink3`. There is no underline and no pill.
- On the right, device status as plain text: the device's name, and only what is wrong ("Server unreachable" in amber, "Shizuku is off" or "Removed from server" in red). Nothing is labelled when all is well.
- App only: at the far right the time and the battery in mono `--ink3`, as a console's system bar shows them. How long ago the device synced is the hint bar's status line on every tab ("Synced 2 min ago"), ticking on its own.

**Sub-tabs.** A second row of text tabs inside a page, such as the emulators on Configs, with `L2` and `R2` hints.

**Cursor row.** The focused row inverts to `--focus-bg` and `--focus-ink`, with a 3 px radius. The hairlines above and below it disappear. This is the only focus style for rows.

**Buttons**
- **Secondary:** a 1.5 px `--rule2` outline, 40 px tall, 3 px radius, 14 px/600.
- **Primary:** filled `--ink` with `--bg` text. There is at most one primary button per pane.
- **Face glyph:** a button that has a gamepad mapping shows its glyph (A, B, X or Y) in a 20 px disc in front of the label.
- **Focused button:** a 2 px `--ink` outline, offset 3 px.

**Hint bar**
- A status line sits on the left.
- On the right, the actions for the current focus, as face glyph plus label: A Open · X Restore · Y Download · B Back.

**Problem rows.** A game with a conflict appears as a normal row pinned to the top of its list, with its text in `--fault` ("Two saves", "choose").

**Facts.** A two-column definition list: labels in `--ink3`, values in `--ink`, and data values in mono.

**Diff**
- Mono 13 px with line numbers in `--ink3` and − / + markers.
- Runs of unchanged lines collapse to "· · · N unchanged lines".
- A row of file names above the diff switches between changed files.

**Checklist marks.**
- Done is a drawn SVG tick: a 2 px stroke in `currentColor`.
- Not done is a 16 px empty circle.
- Progress shows as "9 of 17 done" plus a row of short segments, one per item.

**Inputs and selects**
- A transparent fill with a 1.5 px `--rule2` outline, 40 px tall, 3 px radius.
- The focus style is the same as for buttons.
- Selects use the platform's accessible primitive, never a hand-built one.

## 7. Controller, keyboard and pointer

Every screen must be fully usable with a pointer, a keyboard, or a gamepad.

| Input | Action |
|---|---|
| D-pad / arrow keys | move the cursor |
| A / Enter | open or choose |
| B / Esc | back |
| X / Y | the screen's two secondary actions, named in the hint bar |
| L1 / R1, also `[` and `]` | previous / next page tab |
| L2 / R2, also `{` and `}` | previous / next sub-tab |

- **App:** the hints are always shown. Android delivers gamepad input as key events, so this costs nothing extra.
- **Web:** the bumper and face-glyph hints appear **only while the browser reports a connected gamepad** (Gamepad API). Without one, the hint bar shows the keyboard equivalents, or hides the action column on narrow screens. Buttons keep their labels and drop the glyph discs.
- **Motion:**
  - the cursor moves instantly, with no animation, because people repeat that action constantly;
  - panels and dialogs fade in 150–200 ms with an ease-out curve;
  - with `prefers-reduced-motion`, movement is removed and colour fades stay.
  - app: a page-tab change (L1/R1) fades the content in over 120 ms and slides it 8 dp from the side it came from; with the system's animations off it only fades;
  - app: success lines ("Kept this Thor's save of Pokémon Sword", "Pokémon Sword from Odin 3 is in place.") stand in the hint bar's status place for 5 s, after a tick that strokes in over 200 ms.
- **Haptics and sound (app):** a light tick per cursor or tab step, a firmer confirm on A, X and Y, the platform's reject at a list's end or on a button the screen doesn't offer. The system's touch-feedback setting rules, and Settings › Appearance can turn them off. Three UI sounds (move, open, back; under 40 ms, quiet and dry) are off unless chosen there.

## 8. Screens

The mockups are the reference. Each screen has one focal element.

**Web UI**

| Screen | Focal element | Contents |
|---|---|---|
| Home | the newest-saves list | Columns: system · game · emulator · newest on · other devices · saved. Problem rows are pinned to the top. "Other devices" shows a device's state when it isn't simply "has it": waiting (amber) or "not on Thor" (`--ink3`). One row per game: saves and states are combined. |
| Game | the version list | Save versions on the left (version · from · saved · size · current/pinned/first sync), with save states below them, one row per slot. On the right, details of the focused version: Restore to… (A), Download (Y), Pin (X). Uploading from a PC works by dropping a file anywhere on the page, or with a button. |
| Conflict | the two choices | A red title. Two columns, one per device: change time (marked "a hint only"), size, fingerprint, and a Keep button. Below them, a "Keep both" row with a name for the second copy. A plain statement that nothing has been overwritten. |
| Configs | the diff | Emulator sub-tabs. Left: the group (members, and the note that folder paths stay per device) and its version history. Right: compare two versions, or a version against a device's current files. Actions: Edit (Y), Apply to a device… (X), Download. |
| New-device setup | the remaining items | Title "Set up {device} again", the done count with the segment row, and two columns of checklists: emulators, cores, ROM folders, vault, restore. Configs to restore show their source and linked or copy. |

**Android app** (Compose, 832×468 dp landscape)

| Screen | Contents |
|---|---|
| Main ("This device" tab) | Emulators on the left, with a state per row. The focused emulator's games on the right: newest on, and what it means here. A waiting delivery adds one plain line saying what to do. |
| Tabs | This device · Activity · Conflicts N · Settings. The Conflicts count shows in red only when it isn't zero. |
| Setup | Steps on the left. One question per screen, with the choices as cursor rows. Example from step 4: join a group, copy once, or only back up. |
| Conflicts | The list on the left, the comparison on the right. A keeps this device's save, X keeps the other's, Y keeps both. The hint line says when the choice will be applied, for example after Eden closes. |
| Persistent notification and Shizuku-off state | Same wording as the web, using `--fault` for "Shizuku is off". Not mocked up. The builder follows this system. |

## 9. Not yet designed (left to the plans)

These screens follow the system above:
- Devices: list, pairing with QR and code, rename and revoke.
- Vault.
- Activity: filters and log.
- Settings: account, retention, backups, notifications.
- The editor for editing a config in the browser.
- The app's Activity and Settings tabs, and its first-run sign-in and Shizuku help.

Empty states, loading and errors:
- Each list's empty state is a single sentence in `--ink2` at the list's position. No illustrations.
- Loading leaves the list's rows in place, filled with `--ink3` dashes.
- Errors are stated in the place where they happen, in `--fault`, together with what to do next.

**Name.** The wordmark is plain text, so renaming the product changes only that text.
