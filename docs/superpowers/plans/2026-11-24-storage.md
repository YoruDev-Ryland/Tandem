# Storage page, moving the files, and changing email: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Settings › Storage with Map/Bars/Blocks graphs, a safe live move of the stored files with a short device hold, and email change in the web UI and CLI.

**Architecture:** The server gains a `FilesLocation` singleton (the blob root, persisted in `ServerSettings`) that every blob path goes through, a write gate plus hold flag in `BlobStore`, and a background `FilesMover` driven by admin endpoints. `GET /v1/settings/storage` grows per-game, per-kind and admin server figures. The web Storage page becomes a shell with three view components over one data shape and pure layout helpers in `web/src/lib/storage/`. The app treats `503 server_moving` as a hold and rescans on the new `storage` stream event.

**Tech Stack:** ASP.NET Core .NET 10 + EF Core (SQLite/Postgres), xUnit; Svelte 5 + Vitest; Kotlin + Compose + Robolectric/JUnit.

**Spec:** `docs/superpowers/specs/2026-11-24-storage-design.md`

## Global Constraints

- .NET commands: prefix `export DOTNET_ROOT=$HOME/.dotnet PATH=$HOME/.dotnet:$PATH`. Server tests: `dotnet test tests/Tandem.Server.Tests`. Web: `cd web && npx vitest run`, `npx svelte-check --threshold error`, `npm run build`. App: `cd android && ./gradlew testDebugUnitTest`.
- Only the blobs move. Database, `art/`, title caches and `tmp/` stay under `DataDirectory`.
- Default files location is `<DataDirectory>/blobs` (unchanged layout `<root>/<userId:N>/<aa>/<bb>/<hash>`); existing installs need no migration.
- Setting key `files.location` in `ServerSettings`, JSON `{ "path": string, "id": guid }`; dropped from exported backup settings.
- Marker file name `.tandem-files`, JSON `{ "id": guid }`.
- Error codes: `503 server_moving` with header `Retry-After: 15`; `503 files_unavailable`; `409 move_running`; `400 bad_path`; account: `400 bad_email`, `403 bad_password`, `409 email_taken`.
- Hold aborts the move if in-flight writes don't finish within 60 s.
- Blocks unit: smallest of 1/10/100/1000 MB that keeps used blocks ≤ 200. Map merges games under 2 % of the area into "N more".
- User setting key `storage.view`, values `map` | `bars` | `blocks`, default `map`.
- UI: tokens only (`web/src/styles/tokens.css`); amber = wait, red = problem; console colours only from `SPINES` in `web/src/lib/spines.ts`; no accent colours, gradients, rounded cards or pills; both themes; reduced motion (no animated transitions when `prefers-reduced-motion`).
- Copy is plain and specific. Exact strings fixed by the spec are quoted in the tasks.
- Never delete the old copy without the explicit remove-old request; never write a blob outside the current verified location.

## Review Focus

1. A move target that is on the container's root filesystem (not a mount) must be refused when `/.dockerenv` exists — Task 3 test `Check_refuses_a_folder_that_is_not_a_mount_in_a_container` (mount table and docker flag injected).
2. A blob uploaded during the copy phase must exist in the new location after the switch — Task 4 test `A_blob_written_during_the_copy_is_in_the_new_location`.
3. Server restart after a switch with the NAS folder missing must not recreate it — Task 1 test `A_missing_custom_location_is_not_recreated_and_refuses_blob_writes`.
4. Cancel or failure before the switch deletes only what the job copied and leaves the setting unchanged — Task 4 test `A_failed_move_leaves_the_old_location_and_removes_only_its_copy`.
5. An email change to the same address in different case is not "taken" by the user themselves — Task 6 test `Changing_to_the_same_address_in_another_case_is_allowed`.
