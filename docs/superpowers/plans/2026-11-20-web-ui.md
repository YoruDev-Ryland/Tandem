# Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the console-style web UI (Svelte 5 + Vite) that the server serves at its root URL. First, close the server gaps the UI depends on.

**Architecture:**
- **Server changes (Tasks 1–5):**
  - the four items deferred from the server plan (M-2, M-5, M-6, resolve-winner hardening);
  - a small read model the UI needs: a conflict list, per-device state on each game, and which emulators are running.
- **Web client (Tasks 6–19):**
  - a standalone Vite + Svelte 5 + TypeScript app in `web/`. No SvelteKit: the server already serves `index.html` as the SPA fallback (`Web/WebHosting.cs`).
  - It talks only to the existing `/v1` API with the session cookie, and refetches on SSE `changed` nudges.
  - One shared focus/input system makes every screen work with pointer, keyboard and gamepad.

**Tech Stack:**
- Svelte 5 (runes), Vite, TypeScript (strict).
- Vitest with @testing-library/svelte and jsdom.
- @fontsource for Barlow, Barlow Semi Condensed and JetBrains Mono; `qrcode` for the pairing QR. No other runtime dependencies.
- Server: .NET 10 minimal APIs with xUnit, as before.

**Spec:**
- docs/superpowers/specs/2026-11-20-ui-design.md (the visual and interaction authority).
- docs/superpowers/specs/2026-11-19-emulator-save-config-sync-design.md §8 (product).
- Mockups: design/mockups/web-home.html and design/mockups/web-pages.html.

**Branch:** `feat/web-ui`, created from `feat/ui-design` (which sits on `feat/server`).

**Out of this plan:** the Android UI (see 2026-11-20-android-ui.md). The Android plan uses Tasks 1–5's API additions.

## Global Constraints

**Visual system**
- Every colour comes from the spec §3 tokens: `--bg --ink --ink2 --ink3 --rule --rule2 --focus-bg --focus-ink --wait --fault --glyph --diff-add --diff-del`. No other hex values appear in components.
- Both themes are fully designed. The theme follows `prefers-color-scheme` unless `data-theme="light|dark"` is set on `<html>` (a Settings choice, stored in `localStorage` under `emusync.theme`).
- The banned list in spec §2 applies to every component. In particular:
  - no gradients, glows, shadows or nested containers;
  - no left accent bars;
  - no icons in squares;
  - no status pills or dots on every row;
  - no purple.
- The only radius is 3 px (cursor row, buttons, inputs).
- Type: Barlow Semi Condensed 600 for titles and tabs, Barlow for UI, JetBrains Mono 13 px with tabular numbers for data. Fonts are bundled with @fontsource; nothing loads from Google.
- Sizes and spacing:
  - web side padding 40 px;
  - top bar 72 px, hint bar 56 px;
  - list rows 46 px, detail rows 44 px;
  - 4 px grid.
- Colour only for meaning: `--wait` for waiting and `--fault` for needs-you, on text, never as fills. The one exception is diff line tints.

**Input and behaviour**
- Every screen works by pointer, keyboard and gamepad, with the spec §7 mapping:

  | Gamepad | Keyboard | Action |
  |---|---|---|
  | D-pad | arrows | move the cursor |
  | A | Enter | open / choose |
  | B | Esc | back |
  | X / Y | — | the screen's two secondary actions |
  | L1 / R1 | `[` / `]` | previous / next page tab |
  | L2 / R2 | `{` / `}` | previous / next sub-tab |

- Bumper and face glyphs show only while `navigator.getGamepads()` reports a connected pad.
- The cursor moves instantly. Panels and dialogs fade in over 150–200 ms with `cubic-bezier(0.23,1,0.32,1)`. `prefers-reduced-motion` removes movement.

**Copy and content**
- Copy speaks in games and devices, not sync internals. Example: "Thor, until Eden closes", never "delivery pending".
- Every write that waits for an emulator says so where the user acts.
- Problem rows (open conflict) pin to the top of their list in `--fault`. There is no separate banner.
- Empty states are one sentence in `--ink2`. Loading keeps the row layout with `--ink3` dashes. Errors appear in place, in `--fault`, with the next step.
- The product name appears only as the plain-text wordmark from one constant (`PRODUCT_NAME` in `web/src/lib/brand.ts`). The name is undecided.

**API use**
- Every `/v1` request sends `EmuSync-Protocol: 1` and `credentials: "same-origin"`.
- `EventSource` and download links rely on Task 1's exemption.

**Security**
- No secret ever renders in full. Notification tokens show only "set" / "not set" (`TokenSet`).
- The backup passphrase field is write-only.

**Accessibility**
- Text contrast reaches WCAG AA, 4.5:1, on `--bg` and `--focus-bg` in both themes.
- Real `<button>`, `<a>`, `<input>`, `<select>` and `<dialog>`. No `div` with a click handler.

## Review Focus

1. **Game keys with `/`, spaces, `#` or `?`**: links, routes and API calls must round-trip, e.g. `nds/Pokemon - Platinum Version (USA)`. Test in Task 7: `gamePath`/`parseGamePath` round-trip.
2. **The session expires while the user is on a page**: the next 401 must go to sign-in and return to the same page afterwards. Test in Task 8.
3. **SSE drops and reconnects**: data must not stay stale after reconnect. On reconnect, every visible resource refetches once. Test in Task 7.
4. **Three or four devices and very long game names**: rows keep their columns, names truncate with an ellipsis, and the Home "other devices" column lists them all. Test in Task 11, with a fixture of 4 devices and a 90-character name.
5. **Upload rejected with 413 `too_large` or 409 `conflict_open`**: the message appears in place, says what to do, and the page is unchanged. Test in Task 12.

## Shared vocabulary

- **Device state on a game** (Task 5): `GameDeviceState` with values `Newest`, `HasIt`, `Pending`, `Waiting`, `Behind`, `NotInstalled`, `Differs`.
  - **Pending:** a delivery to that device is not yet acknowledged.
  - **Waiting:** pending while that device reports the game's emulator as running.
  - **Behind:** installed, but its known version isn't the head and no delivery is queued.
- **Copy for each state** (the "other devices" column and the Game page):

  | State | Copy |
  |---|---|
  | Newest | (the "newest on" column) |
  | HasIt | `{device}` |
  | Pending | `{device}, on its way` |
  | Waiting | `{device}, until {Emulator} closes` (`--wait`) |
  | Behind | `{device}, older save` (`--ink2`) |
  | NotInstalled | `not on {device}` (`--ink3`) |
  | Differs | `{device} differs` (`--fault`) |

- **Fingerprint:** the first 8 hex characters of a version's manifest hash.
